# Kia e-Niro battery

> Research for the earlier Home Assistant plan (superseded by the web app on 25 Sep 2026). Kept for reference; many facts still apply.

**Area:** Kia e-Niro 2021 (UK/EU) EV battery level in Home Assistant: free and simple options only

## Recommendation

Include it as an optional, low-priority tile. As of September 2026 it is free and fairly simple to set up, though it can break when Kia changes its login. Use the HACS integration "Kia Uvo / Hyundai Bluelink" (Hyundai-Kia-Connect/kia_uvo v3.15.0, released 2026-09-22, which pins hyundai_kia_connect_api==4.33.1). Choose Region = Europe and Brand = Kia, then enter your normal Kia account email and password. Since library v4.12.0 (May 2026) you no longer need the 2025 reCAPTCHA/refresh-token scripts. Kia's servers started blocking the old login on about 11 Aug 2026, and v4.26.3 (15 Aug 2026) fixed that by logging in through the new Kia app's (OneApp/CCI) login. Keep polling cached: scan interval 30 min (the default) or 60 min. Keep force refresh at the code default of 1440 min, or set the maximum 9999 so HA almost never wakes the car. The car uploads its own status when it is switched off and on some charging events, and every forced wake drains the 12V battery. Put sensor.<nickname>_ev_battery_level on the panel with EV Range, the charging and plugged-in states, and "Last Updated At" so stale data is obvious. Make a tap on the tile open the Kia app (Android package com.kia.oneapp.eu) through fully_kiosk.start_application. If you don't want to maintain a HACS integration, or it breaks and you don't want to troubleshoot, use the fallback: a single button that opens the Kia app. That needs no setup at all.

## Facts

- Integration: domain 'kia_uvo', name 'Kia Uvo / Hyundai Bluelink', version 3.15.0, iot_class cloud_polling, requirements hyundai_kia_connect_api[image]==4.33.1. The HACS minimum HA version is 2025.1. Install through HACS by searching 'Kia Uvo'. _(source: https://raw.githubusercontent.com/Hyundai-Kia-Connect/kia_uvo/master/custom_components/kia_uvo/manifest.json ; https://raw.githubusercontent.com/Hyundai-Kia-Connect/kia_uvo/master/hacs.json ; kia_uvo README.md)_
- The library is actively released: 4.33.1 on 2026-09-22, 4.33.0 on 2026-09-21, 4.32.x on 2026-09-19/20, and so on. The READMEs still say 'Code Maintainers Wanted' (the original author no longer owns a car), but community PRs are being merged. _(source: https://pypi.org/pypi/hyundai-kia-connect-api/json ; library README.rst)_
- The library README says: 'Username/password login is supported directly for Kia, Hyundai, and Genesis (EU) — no browser or manual token extraction needed.' pycryptodome handles the RSA password encryption. _(source: https://raw.githubusercontent.com/Hyundai-Kia-Connect/hyundai_kia_connect_api/master/README.rst)_
- EU login code (KiaUvoApiEU.login): a password matching ^[A-Z0-9]{48}$ is treated as a legacy refresh token. Anything else goes through the plaintext-password 'OneApp/CCI' flow (Kia client_id 01b36c86-79e8-486c-8009-15f2ad88d670, redirect https://oneapp.kia.com/redirect, client-id header com.kia.oneapp.eu). The code comments say this 'bypasses the IDPConnect WAF' (issue #1273). The EU login returns a Token directly, so there is no OTP step in the EU flow (the OTP steps in config_flow are used by other regions). _(source: https://raw.githubusercontent.com/Hyundai-Kia-Connect/hyundai_kia_connect_api/master/hyundai_kia_connect_api/KiaUvoApiEU.py (lines ~192-447))_
- Timeline: password login for EU came back in library v4.12.0 (PyPI 2026-05-16; Discussion #1141). From about 11 Aug 2026 the EU sign-in firewall rejected the old login URL (the one with the :8080 redirect_uri) as an 'abusing request'. v4.26.3 (PyPI 2026-08-15) switched to the OneApp/CCI login to get around it. _(source: https://github.com/Hyundai-Kia-Connect/hyundai_kia_connect_api/discussions/1141 ; https://github.com/Hyundai-Kia-Connect/hyundai_kia_connect_api/pull/1276 ; PyPI upload times)_ **[unverified]**
- The 2025 refresh-token process (Kia-Europe-Login-Flow wiki): solve a Google reCAPTCHA in Chrome with the mobile user agent '..._CCS_APP_AOS', then use the KiaFetchApiTokens.py gist (marvinwankersteen) or the Selenium gist (fuatakgun) to get the refresh_token, and paste it into the password field. This process is now obsolete: its step 4 uses the redirect_uri https://prd.eu-ccapi.kia.com:8080/..., which is the URL pattern now blocked by the WAF. _(source: https://raw.githubusercontent.com/wiki/Hyundai-Kia-Connect/hyundai_kia_connect_api/Kia-Europe-Login-Flow.md)_
- Config flow: pick Region (1=Europe) and Brand (1=Kia), then Username, Password and optional PIN. The token-only step for Europe is commented out in code ('keeping the code since I suspect token based will be back'). A Reconfigure menu offers re-authenticate or set/change PIN. _(source: https://raw.githubusercontent.com/Hyundai-Kia-Connect/kia_uvo/master/custom_components/kia_uvo/config_flow.py)_
- Option defaults and limits in code: scan_interval default 30 min (range 15-999); force_refresh default 1440 min (range 90-9999); no_force_refresh_hour_start 22 and finish 7. The option label reads 'Force Refresh Interval (min), use caution setting this too low as it consumes 12v battery'. The README's '4 hours' and '10PM-6AM' are out of date; the code is authoritative. _(source: kia_uvo custom_components/kia_uvo/const.py, config_flow.py OPTIONS_SCHEMA, translations/en.json)_
- The coordinator polls every min(scan_interval, force_refresh_interval). Outside the no-force hours it calls check_and_force_update_vehicles(force_refresh_interval), which only wakes the car if vehicle.last_updated_at is older than the force interval; otherwise it does a cached update. Inside the quiet hours it only does cached updates. Setting start == finish allows forced refreshes at all hours, so don't do that. _(source: kia_uvo coordinator.py lines ~145-215 ; hyundai_kia_connect_api VehicleManager.py check_and_force_update_vehicle)_
- On an e-Niro (non-CCS2), an EU cached update makes about 3 API calls: GET vehicles/{id}/status/latest, the /location/park lookup ('not a force endpoint so car will not wake up'), and the driving-info call for EVs/PHEVs. A force refresh calls the car directly and wakes it. _(source: KiaUvoApiEU.py update_vehicle_with_cached_state / force_refresh_vehicle_state (lines ~612-730))_
- The EU daily API limit is about 200 calls/day according to the community wiki. The Kia app shares the same quota. When it is exceeded the error is 'The maximum number of daily vehicle checks has been exceeded'. Reports disagree on whether cached calls count or only forced refreshes do. _(source: https://raw.githubusercontent.com/wiki/Hacksore/bluelinky/API-Rate-Limits.md ; kia_uvo issues #636, #918 (search snippets))_ **[unverified]**
- Entity naming: _attr_has_entity_name = True and the device name comes from vehicle.name, which is the car's 'nickname' in the Kia account. That makes entity_id = <domain>.<slug(nickname)>_<slug(translated name)>. For example, nickname 'e-Niro' gives sensor.e_niro_ev_battery_level. _(source: kia_uvo entity.py ; hyundai_kia_connect_api ApiImplType1.py line 226 name=entry['nickname'])_
- Relevant entities: sensor key ev_battery_percentage, named 'EV Battery Level' (%, device_class battery), so sensor.<nick>_ev_battery_level. _ev_driving_range is 'EV Range' (sensor.<nick>_ev_range). _total_driving_range is 'Total Driving Range'. car_battery_percentage is 'Car Battery Level' (12V). last_updated_at is 'Last Updated At' (timestamp). ev_estimated_current_charge_duration is 'Estimated Charge Duration'. ev_charging_power is 'EV Charging Power'. Binary sensors: ev_battery_is_charging is 'EV Battery Charge' (binary_sensor.<nick>_ev_battery_charge) and ev_battery_is_plugged_in is 'EV Battery Plug' (binary_sensor.<nick>_ev_battery_plug). The button force_refresh is 'Force Refresh' (button.<nick>_force_refresh). _(source: kia_uvo sensor.py, binary_sensor.py, translations/en.json)_
- The EU non-CCS2 mapping for an e-Niro: ev_battery_percentage comes from vehicleStatus.evStatus.batteryStatus, charging from vehicleStatus.evStatus.batteryCharge, and plugged-in from vehicleStatus.evStatus.batteryPlugin. _(source: KiaUvoApiEU.py lines 877-891)_
- The integration's services include kia_uvo.update (cached) and kia_uvo.force_update ('ask the vehicle for its latest data — do not overuse!'). For EU, Force Update is marked supported. _(source: kia_uvo README.md)_
- Kia app Android package ids: the new European 'Kia App' is com.kia.oneapp.eu, which is also the client-id the library sends. The legacy EU 'Kia Connect' app (formerly UVO Connect) is com.kia.connect.eu. Kia UK is moving owners from Kia Connect to the new Kia app. _(source: https://play.google.com/store/apps/details?id=com.kia.oneapp.eu ; https://play.google.com/store/apps/details?id=com.kia.connect.eu ; KiaUvoApiEU.py _cci_package_id)_ **[unverified]**
- HA has an action fully_kiosk.start_application that takes device_id and application (the package name). It launches an Android app on the tablet running Fully Kiosk Browser. _(source: https://raw.githubusercontent.com/home-assistant/home-assistant.io/current/source/_actions/fully_kiosk.start_application.markdown)_
- Kia Connect is free for up to 7 years from activation, so a 2021 car should stay free until about 2028. After that a subscription may be needed. _(source: search snippets: connect.kia.com/eu FAQ, Kia Owners Club UK)_ **[unverified]**
- The car pushes its status (including location) to Kia's cloud when it is switched off, and possibly on charge notifications. That is why cached polling is usually good enough without waking the car. _(source: https://github.com/Hyundai-Kia-Connect/kia_uvo/discussions/868 (search snippet))_ **[unverified]**

## Gotchas

- Kia EU login has broken several times: Aug 2025 (reCAPTCHA, needing refresh-token scripts), Oct 2025 (issue #1348), and Aug 11, 2026 (the 'abusing request' firewall block, fixed in v4.26.3 four days later). Expect occasional breakages that are usually fixed within days by a HACS update, sometimes followed by a re-auth. It is 'simple' only if the user is OK updating HACS integrations now and then.
- Don't follow 2025 guides or the 'Kia-Europe-Login-Flow' wiki token scripts. From Sep 2026 you just enter your normal Kia password. The old script's second URL uses the :8080 redirect that the firewall now blocks. A legacy 48-character refresh token is still accepted in the password field, but PR #1322 added recovery for 'wedged' legacy-token logins. If the account was ever set up with a token, reconfigure it with the real password.
- If the Kia account has unaccepted terms, login fails with ConsentRequiredError ('log in via a browser once to accept the terms'). Log into the official Kia app first. The generic invalid_auth message also tells you to log out and back into the official app.
- The entity_id comes from the car's nickname in the Kia account and HA's language when the entity is first created. Check the actual ids under the device page and don't assume sensor.e_niro_ev_battery_level.
- The data is cached cloud data. The battery % can be hours old, for example mid-charge. Show 'Last Updated At' next to it. Don't automate frequent force_update or button presses: each one wakes the car and drains the 12V battery. The minimum force interval enforced in the UI is 90 min.
- The ~200 calls/day EU quota is shared with the phone's Kia app. A cached poll makes about 3 calls on an EV, so 30-minute polling is about 144 calls a day. If the Kia app starts saying 'maximum number of daily vehicle checks exceeded', raise the scan interval to 60.
- README defaults (force refresh every 4 h, quiet hours 22-06) differ from the code defaults (1440 min, 22-07). The code is what actually runs.
- Setting No Force Refresh start == finish allows forced refreshes at all hours; it does not disable them. To effectively disable, set Force Refresh Interval to 9999.
- Security: HA stores the Kia credentials and the integration exposes lock/unlock and climate controls. Don't put lock or climate controls on a wall panel. Log the tablet into HA as a non-admin user.
- The OTP (email/SMS) steps in the config flow are for other regions such as Canada and the USA. EU Kia login returns a token directly with no OTP (verified in KiaUvoApiEU.login).
- Kia Connect is free for about 7 years from activation, so until roughly 2028 for a 2021 car. After that the free part may end.
- The Google Play listing of com.kia.oneapp.eu may not offer the app on tablets. This is UNVERIFIED: check that it installs on the Lenovo M10 before building the tap-to-open button.

## Setup steps

- Log into the official Kia app on your phone. That is 'Kia' (com.kia.oneapp.eu), or the legacy 'Kia Connect' (com.kia.connect.eu). Make sure the e-Niro shows up and Kia Connect is active, accept any pending terms, and note the car's nickname.
- In Home Assistant, install HACS if it isn't there yet. Then HACS > search 'Kia Uvo' (Kia Uvo / Hyundai Bluelink) > Download > restart Home Assistant.
- Go to Settings > Devices & services > Add integration > 'Kia Uvo'. Choose Region: Europe and Brand: Kia. Enter your Kia account email and your normal Kia password (not a token). The PIN is optional and only needed for remote commands; leave it blank if you only want to read data.
- Open the integration > Configure. Keep Scan Interval at 30 (or 60), keep Force Refresh Interval at 1440 (or 9999 to almost never wake the car), and keep quiet hours at 22 to 7.
- Open the car's device page and note the real entity ids (sensor.<nickname>_ev_battery_level, sensor.<nickname>_ev_range, binary_sensor.<nickname>_ev_battery_charge, binary_sensor.<nickname>_ev_battery_plug, sensor.<nickname>_last_updated_at).
- Optional: install the Kia app on the tablet and sign in, so the tile's tap action (fully_kiosk.start_application with com.kia.oneapp.eu) opens it. You'll need the Fully Kiosk integration's device_id.
- If login ever fails after a Kia change, update the integration in HACS, restart, and use Reconfigure > Re-authenticate. If you don't want to deal with that, delete the integration and keep only the Kia app button.
