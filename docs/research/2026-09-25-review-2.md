# Review 2 (Home Assistant version)

> Code review findings (all fixed at the time). Kept as a record.

_Workflow: Review the wall-panel repo on given dimensions, then adversarially verify every finding_

- **[major] dashboard-config:** The Agile price card breaks on the compact layout the docs promise for the TB-X306F (960x600), and on 1280-wide screens shorter than about 736px (for example a 1280x800 tablet with the status and nav bars showing). The 'Agile price now' label overlaps the big price, and the second sub line runs past the card's right edge, which cuts off 'tomorrow'. (homeassistant/dashboard/wall-panel.yaml) → 
- **[major] dashboard-config:** If you follow the documented 'delete the e-Niro tile' step, the paste fails. The visible e-Niro tile is the anchor `&tile_car`, and the compact grid reuses it through an alias on line 270 (`- {<<: *tile_car, features: []}`), which doesn't mention e-Niro, so a novice won't know to delete it. Deleting or blanking the `car_battery` settings line breaks the paste the same way. (docs/dashboard.md) → 
- **[minor] dashboard-config:** The merge-key overrides give the same result in js-yaml 4, js-yaml 5 (the frontend) and HA's Python loader. But in YAML mode (docs Option B), HA's loader logs 4 WARNING lines about 'duplicate key' every time the dashboard file loads, which makes a correct file look broken. (homeassistant/dashboard/wall-panel.yaml) → 
- **[minor] dashboard-config:** If the `octopus_rate` ID is wrong (a typo in the settings block, which the user edits by hand) or the entity is missing, the whole price card turns into a cryptic JS error card. It doesn't fall back to the '–' / 'Waiting for prices…' the template was written to show. (homeassistant/dashboard/wall-panel.yaml) → 
- **[minor] dashboard-config:** The comment says the launcher works in Chrome ('Companion app / Chrome (which hand intent: links to Android)'). It doesn't. Chrome rewrites web-initiated intents so they can only reach BROWSABLE activities. Spotify and Keep's MAIN/LAUNCHER intents, the HOME intent and Claude's explicit component all fail. For Spotify and Keep, Chrome opens the Play Store listing instead, because package= is set. (homeassistant/dashboard/wall-panel.yaml) → 
- **[minor] dashboard-config:** Pasting this file, which has many comments, into the Raw configuration editor and pressing Save brings up a confirm() dialog the guide doesn't mention: 'Your configuration might contain comments, these will not be saved. Do you want to continue?' If the user clicks Cancel, nothing is saved. (docs/dashboard.md) → 
- **[minor] dashboard-config:** `kiosk_mode: kiosk: true` hides this dashboard's whole header, so the ⋮ menu (Refresh) and the pencil (Raw configuration editor, for re-pasting later) can't be reached without ?disable_km. That note only appears later, in section 4. In YAML mode the ⋮ Refresh isn't needed anyway. (docs/dashboard.md) → 
- **[minor] dashboard-config:** `fit_mode: cover` in a fixed 16:9 box crops any non-16:9 stream. Nest doorbells (listed in docs/integrations/nest.md as 'Always-live tile') stream in portrait. The Nest Doorbell (battery / wired 2nd gen) is 3:4 (960×1280, per Google's spec sheet, from memory; web search budget exhausted, so not re-checked this session). So only the middle ~42% of the doorbell's height shows, and faces and parcels at the door get cut off. (homeassistant/dashboard/wall-panel.yaml) → 
- **[nit] dashboard-config:** At 960x600 and 1024x600 there's an empty dark band under the camera video, 23px and 8px tall. Grid row 1 is `auto`, and its height comes from the 4-row clock-weather card, not from the 16:9 camera box. The extra height is also taken from the already-cramped price card. (homeassistant/dashboard/wall-panel.yaml) → 
- **[nit] dashboard-config:** The chart and the big price can show different colours for the same price, although the docs (dashboard.md line 79) say both use the same thresholds. (a) At exactly 0p the chart bar is green but the big price is blue, because ApexCharts applies ranges in order and the last match wins. (b) The price colour is picked from the unrounded value but shown rounded: 14.955p displays as '15.0p' in green, while the chart bar (rounded to 15.0) is amber. (homeassistant/dashboard/wall-panel.yaml) → 
- **[nit] dashboard-config:** 'cheapest ahead' can pick the current slot, because the reduce starts from rates[i]. It then prints that slot's start time, which has already passed. For example, at 04:20 it shows 'cheapest ahead: 0.0p at 04:00', and at 23:50 with no tomorrow prices it shows '… at 23:30'. (homeassistant/dashboard/wall-panel.yaml) → 
- **[nit] dashboard-config:** The comment says to replace the example serial_MPAN 'in all six lines', but there are only five settings lines (26-30). The sixth occurrence is the comment itself, so a careful user will go looking for a line that doesn't exist. (homeassistant/dashboard/wall-panel.yaml) → 
- **[nit] dashboard-config:** The comment says the padding gives 'even 8px gutters'. The gaps between columns are 8px, but between rows they are 12px, the top edge is 12px and the bottom edge 8px. That's because layout-card's per-card margin is 4px 4px 8px (top, sides, bottom). (homeassistant/dashboard/wall-panel.yaml) → 
- **[major] docs-tablet-voice:** The docs state as fact that the Claude button opens Claude in voice mode, on 'the same screen Android shows when Claude is set as the assistant', and that it 'is designed for talking to Claude'. Nobody has checked that on a device. The only hedge is that a future app update might break it. The docs never say it may already open a text or dictation overlay today, or may not start at all while Claude is not the default assistant. Voice mode is a core requirement in the brief, so this claim needs more care than the others. (docs/voice-and-apps.md) → 
- **[major] docs-tablet-voice:** The docs say to add ?disable_km on the tablet 'to edit' the dashboard. The tablet is logged in as the non-admin `panel` user, and Home Assistant only shows 'Edit dashboard' to admins, so the tablet can never edit, with or without ?disable_km. In the other direction, `kiosk_mode: {kiosk: true}` at the root hides the header for every user, including the admin on a PC. As soon as the pasted config is saved, the admin's own header disappears (including Edit and Done), and the docs only mention ?disable_km 'on the tablet'. Fully also has no address bar by default, so 'open the start URL with ?disable_km' has no instructions for how to do it. (docs/tablet.md) → 
- **[major] docs-tablet-voice:** The Start URL row offers the IP address as an alternative when homeassistant.local doesn't resolve. That is likely on Android 10/11 M10s and many routers. The URL whitelist row only gives `http://homeassistant.local:8123/*`. A user who switches to the IP but copies the whitelist as written sets a whitelist that doesn't match the start page, so Fully refuses to load the panel. Troubleshooting only mentions the whitelist under 'No button opens anything', not under 'blank or blocked page'. (docs/tablet.md) → 
- **[major] docs-tablet-voice:** The dashboard has two e-Niro tiles. The full one defines the YAML anchor `&tile_car` (wall-panel.yaml line 239), and the compact grid reuses it with `{<<: *tile_car, features: []}` (line 270). If you delete 'the e-Niro tile' (the visible, anchored one), the alias is left with nothing to point to. The paste then fails with a YAML 'unidentified alias' error, and a YAML-mode dashboard fails to load. If you delete only one of the two, the tile still shows on the other screen size. The Kia is optional in the brief, so many users will try this step. (docs/dashboard.md) → 
- **[minor] docs-tablet-voice:** The Companion-app route has you log in as the non-admin `panel` user and then go to 'Settings → Companion app → Other settings → Keep screen on'. Home Assistant's Settings panel is admin-only, so that path doesn't exist for `panel`. The Companion app shows an 'App settings' sidebar item instead, and kiosk-mode hides the sidebar on the wall-panel dashboard. The section also never says how to make the app open the wall-panel dashboard rather than Overview after a restart. (docs/tablet.md) → 
- **[minor] docs-tablet-voice:** The suggested fix, allowing 'Display over other apps', has nothing to do with dashboard links. The Companion app only asks for or checks that permission for the notification commands command_activity and command_launch_app. Buttons that open app:// or intent: links go through the WebView URL interceptor, which never checks it. A user with broken buttons would be sent the wrong way. (docs/troubleshooting.md) → 
- **[minor] docs-tablet-voice:** Several features start Fully from the background: Launch on boot, and the package's HA-triggered 'Bring to foreground' (the 10-minute return to the panel, and waking for the doorbell). Since Android 10, apps can't start an activity from the background unless they hold 'Display over other apps' (SYSTEM_ALERT_WINDOW). The guide never tells the user to grant Fully this permission. Without it, 'the panel also comes back by itself after 10 minutes' and the doorbell wake can silently do nothing on every M10 running Android 10 or later. (docs/tablet.md) → 
- **[minor] docs-tablet-voice:** No source supports this. Adding household members' Voice Match from their own phones through Google Home works for shared Nest speakers and displays (and a docked Pixel Tablet), not for a normal Android tablet. On a Lenovo M10, Voice Match trains the signed-in account on that device, and personal answers (Keep, Calendar) come from that one account. The doc also doesn't say that other people's 'Hey Google' may be less reliable on a personal device. (docs/voice-and-apps.md) → 
- **[minor] docs-tablet-voice:** The guide sets Screen lock to None and puts a Home button on a shared wall panel, but never says that whichever Google account is signed in is then fully open. Anyone in the house or a visitor can ask Gemini for that account's email or calendar, and can open Gmail, Photos or Chrome through the Home button. The guide carefully uses a non-admin HA user 'so a visitor poking at it can't change settings', yet leaves the Google side open. (docs/tablet.md) →
