# Octopus Energy: Agile prices and Home Mini

> Research for the earlier Home Assistant plan (superseded by the web app on 25 Sep 2026). Kept for reference; many facts still apply.

**Area:** Octopus Energy (UK): live usage from the Octopus Home Mini and Agile prices, using the BottlecapDave HomeAssistant-OctopusEnergy integration

## Recommendation

Use BottlecapDave's HomeAssistant-OctopusEnergy integration (it is in the default HACS store; latest release is v19.2.1 from 2026-09-19 and it needs HA 2025.11.0 or newer). Set it up in the UI with the Octopus account number (A-XXXXXXXX) and an API key. In the "Home Mini settings" section, tick "I have a Home Mini" and leave the electricity refresh at the default of 1 minute. That gives sensor.octopus_energy_electricity_<serial>_<mpan>_current_demand in watts for live usage, plus today's kWh and £ sensors. For prices, the event.octopus_energy_electricity_<serial>_<mpan>_current_day_rates and _next_day_rates entities are enabled by default. Each has a `rates` list of {start, end, value_inc_vat, is_capped, is_intelligent_adjusted}, plus min_rate, max_rate and average_rate. The current_rate, next_rate and previous_rate sensors come in GBP/kWh, so multiply by 100 to show pence. Agile still uses 30-minute slots (48 a day; tomorrow's prices appear after about 4pm). The integration also splits every tariff into 30-minute slots, so the user's "15 min price" should be treated as the half-hourly Agile price. For the panel, the simplest good-looking option is the HACS card lozzd/octopus-energy-rates-card: a colour-coded table of the rest of today (showpast: false) plus tomorrow via futureEntity. Pair it with a current-price tile, a gauge for current_demand, and optionally the integration's own apexcharts-card bar chart. For "cheapest time", note that the built-in target rate sensors were removed in v18.0.0. Use the companion Target Timeframes integration instead: a data source with id octopus_energy_<MPAN>_<SERIAL> is fed automatically. For a display-only panel, a template sensor over the rates attribute is simpler.

## Facts

- Integration domain is octopus_energy, repo BottlecapDave/HomeAssistant-OctopusEnergy, manifest version 19.2.1 (CHANGELOG 2026-09-19), iot_class cloud_polling. hacs.json sets minimum HA version 2025.11.0. It is in the default HACS store (no custom repository needed). There is no Octopus integration in HA core (home-assistant.io has no octopus_energy page). _(source: https://github.com/BottlecapDave/HomeAssistant-OctopusEnergy/blob/develop/custom_components/octopus_energy/manifest.json ; hacs.json ; README.md)_
- Setup is done only in the UI (config flow 'Octopus Energy Account'). Required fields: account_id ('Account ID (e.g. A-AAAA1111)') and api_key. The API key is at https://octopus.energy/dashboard/new/accounts/personal-details/api-access. Other fields: calorific_value (default 40), favour_direct_debit_rates, auto_discover_cost_trackers, plus collapsible sections home_mini_settings, home_pro_settings, price_cap_settings and intelligent_settings. _(source: custom_components/octopus_energy/config_flow.py lines 138-241; translations/en.json)_
- To enable the Home Mini, tick the checkbox 'I have a Home Mini' (key home_mini_settings.supports_live_consumption). Refresh settings are 'Home Mini electricity refresh rate in minutes' (live_electricity_consumption_refresh_in_minutes, default 1, minimum 1) and the gas equivalent (default 2). These can be changed later through Reconfigure. _(source: custom_components/octopus_energy/const.py lines 37-57; config_flow.py; config/main.py; _docs/setup/account.md#home-mini)_
- Rate limit: Octopus APIs allow 100 calls per hour, shared across everything including the Octopus app and other integrations. Electricity at 1 minute plus gas at 2 minutes is about 90 calls per hour. 'Too many requests' errors that mention smartMeterTelemetry mean the refresh interval should be raised. _(source: _docs/setup/account.md#refresh-rate-in-minutes ; _docs/faq.md 'I am getting errors relating to Too many requests')_
- Home Mini data does not come from the device locally. It is polled from Octopus's cloud (GraphQL smartMeterTelemetry, grouping HALF_HOURLY, reading readAt/consumption/consumptionDelta/demand/export). The current_demand value is taken from the latest record's 'demand' field. _(source: custom_components/octopus_energy/api_client/__init__.py lines 129-142, 1470-1500; electricity/current_demand.py; _docs/faq.md (Home Mini stopped updating))_
- Live power: sensor.octopus_energy_electricity_{{METER_SERIAL_NUMBER}}_{{MPAN_NUMBER}}_current_demand. Unit is W, device_class power, state_class measurement. It tries to update every minute with a Home Mini (every 10 s with a Home Pro). It is enabled by default and only created when 'I have a Home Mini' is ticked (import meter only). _(source: custom_components/octopus_energy/electricity/current_demand.py ; sensor.py lines 427-456 ; _docs/entities/electricity.md#current-demand)_
- Other Home Mini entities: sensor..._current_accumulative_consumption (kWh today; attributes total and charges[] per 30 min), sensor..._current_accumulative_cost (GBP today including standing charge; attributes standing_charge, total_without_standing_charge, total, charges[] with rate/consumption/cost), and sensor..._current_total_consumption (lifetime kWh). These are enabled by default when the meter is smart. sensor..._current_consumption (a delta) and sensor..._current_interval_accumulative_consumption are disabled by default. _(source: _docs/entities/electricity.md 'Home Mini/Pro Entities'; electricity/current_*.py entity_registry_enabled_default)_
- Rate sensors: sensor.octopus_energy_electricity_{{SERIAL}}_{{MPAN}}_current_rate, _previous_rate and _next_rate. Unit is 'GBP/kWh' in pounds, e.g. 0.2345 = 23.45p, including VAT. current_rate attributes: mpan, serial_number, is_export, is_smart_meter, tariff, start, end, is_capped, is_intelligent_adjusted, current_day_min_rate, current_day_max_rate, current_day_average_rate, price_cap. next_rate and previous_rate give the next or previous rate that is DIFFERENT from the current one (unknown if there isn't one), with start and end attributes. _(source: _docs/entities/electricity.md (Current Rate / Previous Rate / Next rate); electricity/current_rate.py native_unit_of_measurement)_
- Rate event entities: event.octopus_energy_electricity_{{SERIAL}}_{{MPAN}}_previous_day_rates, _current_day_rates and _next_day_rates. The state is the timestamp of the last update. Attributes: rates (list), tariff_code, serial_number, mpan, and (from code and events.md) min_rate, max_rate, average_rate. Each rate item has start (datetime, UTC), end, value_inc_vat (GBP/kWh), is_capped and is_intelligent_adjusted. Export meters add '_export' before the suffix. These have been enabled by default since v9.0.1 (2023-11-22); the older docs and rates-card README that say 'disabled by default' are out of date. _(source: _docs/entities/electricity.md; _docs/events.md; coordinators/__init__.py __raise_rate_event; electricity/rates_current_day.py; CHANGELOG.md v9.0.1)_
- Entity IDs are built with generate_entity_id(slugify(unique_id)), so the meter serial appears in LOWER CASE, e.g. event.octopus_energy_electricity_22l4132637_1900026354329_current_day_rates (the example in the rates-card README). _(source: custom_components/octopus_energy/electricity/base.py; lozzd/octopus-energy-rates-card README)_
- Agile is still HALF-HOURLY in Sept 2026: 48 slots a day, next-day prices published after about 16:00 UK time. Separately, the integration splits every tariff into 30-minute slots (rates_to_thirty_minute_increments), and the rates coordinator requests from yesterday 00:00 to the day after tomorrow 00:00. I found no evidence of a 15-minute Agile product; GB settlement is still 30 minutes, with Elexon's MHHS due to finish in Dec 2026. _(source: custom_components/octopus_energy/api_client/__init__.py lines 619-676; coordinators/electricity_rates.py lines 73-74; web search (octopus.energy/smart/agile, elexon.co.uk half-hourly-settlement))_
- Refresh intervals: account every 6 h, rates every 15 min (stops once the requested period is filled), Home Mini configurable (minimum 1 min), previous-day consumption every 30 min, standing charges every 60 min. Failed calls back off up to a maximum of 30 min. _(source: custom_components/octopus_energy/const.py lines 4-17; _docs/faq.md 'How often is data refreshed?')_
- Target rate sensors were REMOVED from the Octopus integration in v18.0.0 (2026-02-21). The replacement is the separate HACS integration BottlecapDave/HomeAssistant-TargetTimeframes (v1.5.2). Since v18.1.0 the Octopus integration fires 'target_timeframe_update_data_source' with data_source_id 'octopus_energy_{mpan}_{serial_number}' whenever rates change. A Target Timeframes data source with that id (matched case-insensitively) is filled automatically, with no blueprint needed. Sensors are named binary_sensor.target_timeframes_{DATA_SOURCE_ID}_{NAME}. Attributes include target_times, next_time, next_average_value, next_duration_in_hours, current_average_value and overall_min_value. Hours are set in 0.5 increments. _(source: _docs/architecture_decision_records/0001_target_rates_removal.md; _docs/migrations/target_timeframes.md; CHANGELOG.md v18.0.0/v18.1.0; const.py lines 158-159; TargetTimeframes _docs/setup/target_timeframe.md, data_source.md, entities/*.py)_
- lozzd/octopus-energy-rates-card (HACS default, frontend) shows a colour-coded 30-minute price table. Main keys: currentEntity (required), pastEntity, futureEntity, cols, showpast, showday, hour12, title, unitstr, lowlimit, mediumlimit, highlimit, roundUnits, cheapest, multiplier (100 for pence), rateListLimit, cardRefreshIntervalSeconds (default 60), exportrates, targetTimesEntities, additionalDynamicLimits. Plunge (negative) prices are shown in blue. _(source: https://raw.githubusercontent.com/lozzd/octopus-energy-rates-card/main/README.md (repo cloned, last commit 2026-01-16))_
- apexcharts-card (RomRider, v2.2.3) options used here: graph_span, span.start/end/offset, now.show/label/color (the marker only moves when the card updates, so set update_interval), update_interval, series.data_generator (returns [ms, value][]), series.transform, series.time_delta (v2.0.0), series.offset (negative values only), show.in_header/in_chart/legend_value, float_precision. _(source: https://raw.githubusercontent.com/RomRider/apexcharts-card/master/README.md)_
- For information only (the user is on Agile, not Intelligent): v19.0.0 added sensor.octopus_energy_{{DEVICE_ID}}_intelligent_state_of_charge, the EV battery %, but it exists only for Intelligent Octopus devices. So it will NOT cover the Kia e-Niro on Agile. _(source: _docs/entities/intelligent.md#state-of-charge; CHANGELOG.md v19.0.0)_
- The current Agile product code is AGILE-24-10-01 (tariff E-1R-AGILE-24-10-01-<region letter>). The public, unauthenticated endpoint is https://api.octopus.energy/v1/products/AGILE-24-10-01/electricity-tariffs/E-1R-AGILE-24-10-01-<REGION>/standard-unit-rates/. This matters only for a non-HA fallback. _(source: web search snippet (tomasmcguinness.com 2026-01, octopus docs); api.octopus.energy was blocked from this sandbox)_ **[unverified]**

## Gotchas

- Agile is 30-minute, not 15-minute. The integration also splits all rates into 30-minute slots in code. Tell the user the panel shows the half-hourly price. If Octopus ever moves to 15-minute slots, the integration and cards would need an update.
- All price values (current_rate state, value_inc_vat, current_day_min/max/average_rate, min_rate/max_rate) are in POUNDS per kWh (GBP/kWh). Multiply by 100 for pence (multiplier: 100 on the rates card, * 100 in apexcharts, or a template sensor). HA cannot convert the GBP/kWh unit through the UI.
- Entity IDs contain the meter serial in lower case plus the 13-digit MPAN, e.g. ..._22l4132637_1900026354329_... Copy the real IDs from Settings > Entities (search 'current_rate') rather than typing them.
- next_rate and previous_rate are the next or previous DIFFERENT price, not necessarily the adjacent slot. If two slots in a row cost the same, next_rate skips ahead. Use the next_day_rates / current_day_rates event attributes for an exact timeline.
- next_day_rates is empty until Agile prices are published, usually after about 16:00 and sometimes later. Guard data_generator code with (entity.attributes.rates || []). The integration rechecks every 15 minutes.
- DST change days have 46 or 50 slots. Rate start/end are UTC datetimes, so format them with as_timestamp(...)|timestamp_custom or new Date() in the frontend.
- Home Mini data goes through Octopus's cloud, not the local network. If current_demand goes stale, first check live data shows in the Octopus app or website. The FAQ says the Mini can freeze in hot weather and a power-cycle fixes it.
- API limit is 100 calls/hour shared with the Octopus app. Electricity at 1 minute plus gas at 2 minutes is about 90/hour, so running the Octopus app on the tablet as well may cause 'Too many requests' (smartMeterTelemetry) errors. Raise the gas interval if that happens.
- The rates-card README and the integration's community.md still say the rate event entities are disabled by default. That has not been true since v9.0.1. The rates-card README's targetTimesEntities link to 'target_rate' docs is also out of date: target rate sensors were removed in v18.0.0 and replaced by Target Timeframes.
- The integration's apexcharts example uses graph_span: 1d with span start: day, so its next_day_rates series falls outside the visible window. To see tomorrow, use graph_span: 48h as in the second example. The '-15min' series offset in the upstream example assumes 30-minute bars. apexcharts-card documents series offset as negative-only, meant for overlaying past data, so time_delta: '+15min' is the cleaner way to centre bars.
- apexcharts 'now' marker and the rates card only redraw on card update. Set update_interval (e.g. 5min) or cardRefreshIntervalSeconds, or the marker will freeze on a kiosk that stays open for days.
- The integration only reads the FIRST active property on the account. Meters with no active agreement are skipped.
- The Intelligent state-of-charge sensor (v19.0.0) does not apply to Agile customers, so it cannot supply the Kia e-Niro battery level unless the user switches to Intelligent Octopus Go and links the car.

## Setup steps

- Make sure the Home Mini is paired and live usage shows in the Octopus app or website (octopus.energy > My energy). The integration only exposes what the app sees.
- Get the Octopus account number (A-XXXXXXXX, shown on bills or at the top of https://octopus.energy/dashboard) and generate or copy an API key at https://octopus.energy/dashboard/new/accounts/personal-details/api-access. Treat the key as a secret.
- In Home Assistant (with HACS installed): HACS > search 'Octopus Energy' (BottlecapDave) > Download > restart HA.
- Settings > Devices & services > Add integration > 'Octopus Energy' > 'Account'. Enter the Account ID and API key. Expand 'Home Mini settings', tick 'I have a Home Mini', leave the electricity refresh at 1 min, and set gas to 2-5 min if gas is shown. Leave price cap and intelligent settings blank. Submit.
- Open Settings > Entities, search 'octopus_energy_electricity' and note the serial_mpan part of the IDs (e.g. current_rate, current_demand, current_day_rates, next_day_rates). Wait up to about 15 minutes for rates to fill in.
- HACS > Frontend: download 'Octopus Energy Rates Card' (lozzd) and/or 'apexcharts-card' (RomRider), then hard-refresh the tablet browser or Fully Kiosk cache.
- Add the dashboard cards: rates table (currentEntity + futureEntity, showpast: false, multiplier: 100), a current price tile or template sensor in pence, a gauge on current_demand, and today's kWh/£ tiles.
- Optional 'cheapest time' automation: HACS > download 'Target Timeframes' (BottlecapDave) > add integration > create a data source named 'Octopus Energy Import' with id octopus_energy_<MPAN>_<SERIAL>. It fills automatically. Then add a 'Target timeframe' sub-entry (e.g. 2 hours, continuous) to get binary_sensor.target_timeframes_octopus_energy_<mpan>_<serial>_<name> with a next_time attribute.

## Open questions

- Did the user actually mean a 15-minute price? Agile is half-hourly, so should the panel say '30-min slot' (recommended) or also show a per-15-minute view?
- Should the rates widget show only the rest of today, or also tomorrow once prices are published after about 4pm? This decides graph_span 24h vs 48h and whether futureEntity is used.
- Does the user also have gas on the Home Mini, or export (solar)? This affects the API call budget and extra entities (_export_current_day_rates has no Home Mini export demand).
- Preferred visual: colour-coded table (rates card), bar chart (apexcharts), or both? Colour thresholds (low/medium/high pence) should be picked with the user.
- Is a 'cheapest remaining slot' readout wanted (template sensor, display only), or real automations (Target Timeframes)?
- UNVERIFIED: whether the adapted apexcharts snippet with time_delta '+15min' and data_generator renders as intended on apexcharts-card v2.2.3. It has not been tested on a live HA instance.
